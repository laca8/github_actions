1️⃣ مقدمة: إيه هو CI/CD؟

CI — الدمج المستمر (Continuous Integration)

كل مرة المطوّر يعمل push أو Pull Request، بيتم تلقائيًا: فحص الكود، تشغيل الاختبارات، بناء المشروع.

CD — النشر المستمر (Continuous Deployment / Delivery)

بعد ما الكود يعدي كل الفحوصات، يترفع تلقائيًا لبيئات مختلفة:

  • Dev → بيئة التطوير
  • Staging → بيئة تحاكي الإنتاج
  • Production → البيئة الفعلية للمستخدمين
الهدف: تقليل الأخطاء البشرية · سرعة النشر · جودة أعلى للكود · ثقة أكبر في كل إصدار.

2️⃣ مراحل CI بالتفصيل

🔹 Checkout — سحب الكود

سحب الكود من GitHub على سيرفر الـ CI عشان نشتغل عليه.

- name: Checkout code
  uses: actions/checkout@v4

🔹 Caching + Install — الكاش وتثبيت المكتبات

بدون cache، كل مرة الـ Pipeline بيشتغل بيحمّل كل المكتبات من الصفر. الكاش بيخزّن ~/.npm عشان المرة الجاية يكون أسرع بـ 10 مرات.

- name: Setup Node.js with Cache
  uses: actions/setup-node@v4
  with:
    node-version: '20'
    cache: 'npm'          # ← كاش تلقائي لـ ~/.npm

- name: Install dependencies
  run: npm ci             # ← أسرع من npm install مع الكاش
ليه npm ci مش npm install؟
المقارنة npm install npm ci
السرعة أبطأ أسرع (مع cache)
package-lock.json ممكن يغيّره بيستخدمه زي ما هو
node_modules بيضيف عليه بيمسحه ويعمل من الصفر
مناسب لـ التطوير المحلي CI/CD
كاش يدوي (للحالات الخاصة):
- name: Cache node_modules
  uses: actions/cache@v4
  with:
    path: ~/.npm
    key: ${{ runner.os }}-node-${{ hashFiles('**/package-lock.json') }}
    restore-keys: |
      ${{ runner.os }}-node-

🔹 Lint — فحص جودة الكود

فحص تنسيق الكود وكشف الأخطاء الشكلية باستخدام ESLint.

- name: Run ESLint
  run: npm run lint

🔹 API & Unit Tests — اختبارات الـ API

اختبار صحة استجابة الـ Endpoints (مثل / و /health) باستخدام Jest و Supertest للتأكد إن السيرفر شغال وسليم.

- name: Run Tests
  run: npm test

🔹 Build — بناء المشروع

بناء نسخة جاهزة للتشغيل في بيئة الإنتاج.

- name: Build project
  run: npm run build

🔹 Security Scanning — فحص الأمان

فحص الثغرات في المكتبات باستخدام npm audit.

- name: Security audit
  run: npm audit --audit-level=high

3️⃣ Artifact — الناتج النهائي

الناتج النهائي بعد الـ Build (زي مجلد dist/ أو ملفات المشروع). بيتخزن على GitHub عشان يتستخدم في الـ CD بدون إعادة بناء.

- name: Upload artifact
  uses: actions/upload-artifact@v4
  with:
    name: app-build
    path: .

4️⃣ Environment Variables — المتغيرات البيئية

في الـ CI/CD عندك 3 أنواع من المتغيرات:

أ) Secrets — البيانات الحساسة 🔒

كلمات السر، API Keys، مفاتيح SSH. مش بتظهر في الكود ولا في الـ Logs.

المكان: GitHub → Settings → Secrets and variables → Actions

steps:
  - name: Use secret
    env:
      DB_PASSWORD: ${{ secrets.DB_PASSWORD }}
      API_KEY: ${{ secrets.API_KEY }}
    run: echo "Connecting to database..."

ب) Environment Variables — متغيرات البيئة 🌍

URLs، Ports، أسماء البيئات. بتتغير حسب كل Environment.

المكان: GitHub → Settings → Environments → (اختر البيئة) → Environment variables

jobs:
  deploy-production:
    environment: production
    steps:
      - run: echo "URL is ${{ vars.SERVER_URL }}"

ج) Workflow Variables — متغيرات الملف ⚙️

متغيرات ثابتة مش حساسة، بتتحط جوه ملف الـ YAML نفسه.

env:
  NODE_ENV: production
  APP_PORT: 3000

jobs:
  build:
    steps:
      - run: echo "Port is $APP_PORT"

5️⃣ مراحل CD بالتفصيل

🔹 Deploy Dev

نشر أولي على بيئة التطوير للتجربة السريعة.

🔹 Deploy Staging

نشر على بيئة تحاكي الإنتاج تمامًا للاختبار النهائي.

🔹 Approval — الموافقة اليدوية

بوابة أمان: موافقة يدوية من مسؤول قبل النشر على الإنتاج.

environment:
  name: production
  # فعّل "Required reviewers" في إعدادات GitHub Environment

🔹 Deploy Production

النشر الفعلي. الكود بيوصل للمستخدمين الحقيقيين.

6️⃣ Deploy حقيقي على سيرفر بالـ SSH

بنستخدم SSH عشان نوصل للسيرفر ونشغّل أوامر عليه تلقائيًا بعد كل push.

الخطوة 1: جهّز Secrets في GitHub

GitHub → Settings → Secrets and variables → Actions

Secret Name القيمة
DEV_HOST IP السيرفر أو الدومين
DEV_USER اسم اليوزر (مثلاً: ubuntu)
DEV_SSH_KEY محتوى ملف Private Key كامل

الخطوة 2: SSH Action — تشغيل أوامر على السيرفر

- name: Deploy via SSH
  uses: appleboy/ssh-action@v1
  with:
    host: ${{ secrets.DEV_HOST }}
    username: ${{ secrets.DEV_USER }}
    key: ${{ secrets.DEV_SSH_KEY }}
    script: |
      cd /var/www/my-app
      git pull origin main
      npm ci --production
      pm2 restart my-app
      echo "✅ Deployed!"
✅ ليه PM2؟ بيخلي التطبيق يشتغل في الخلفية، بيعمل restart تلقائي لو وقع، وبيسجّل الـ Logs.

7️⃣ Monitoring — المراقبة

بعد النشر، بنراقب الأداء والأخطاء باستمرار:

  • New Relic — أداء التطبيقات
  • Datadog — البنية التحتية
  • Prometheus + Grafana — مقاييس ورسوم بيانية

📄 src/app.js

const express = require("express");

const app = express();

app.use(express.json());

app.get("/", (req, res) => {
    res.json({
        message: "Hello from GitHub Actions",
    });
});

app.get("/health", (req, res) => {
    res.json({
        status: "ok",
        message: "Server is healthy",
    });
});

module.exports = app;

📄 src/server.js

const app = require("./app");

const PORT = process.env.PORT || 3000;

app.listen(PORT, () => {
    console.log(`Server running on port ${PORT}`);
});

📄 test/api.test.js

const request = require("supertest");
const app = require("../src/app");

describe("Express API Endpoints", () => {
    it("GET / should return welcome message", async () => {
        const res = await request(app).get("/");
        expect(res.statusCode).toEqual(200);
        expect(res.body.message).toBe("Hello from GitHub Actions");
    });

    it("GET /health should return ok status", async () => {
        const res = await request(app).get("/health");
        expect(res.statusCode).toEqual(200);
        expect(res.body.status).toBe("ok");
        expect(res.body.message).toBe("Server is healthy");
    });
});

9️⃣ ملف GitHub Actions الكامل

بيجمع: Caching + Secrets + Env Vars + SSH Deploy + PM2

name: CI/CD Pipeline

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

env:
  NODE_ENV: production

jobs:

  # ══════════ CI ══════════
  ci:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Setup Node + Cache
        uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'

      - run: npm ci
      - run: npm run lint
      - run: npm test
      - run: npm audit --audit-level=high

      - uses: actions/upload-artifact@v4
        with:
          name: app-files
          path: .

  # ══════════ CD ══════════
  deploy-dev:
    needs: ci
    runs-on: ubuntu-latest
    environment: dev
    steps:
      - uses: actions/download-artifact@v4
        with:
          name: app-files

      - name: Deploy to Dev Server via SSH
        uses: appleboy/ssh-action@v1
        with:
          host: ${{ secrets.DEV_HOST }}
          username: ${{ secrets.DEV_USER }}
          key: ${{ secrets.DEV_SSH_KEY }}
          envs: NODE_ENV,DB_PASSWORD
          script: |
            cd /var/www/my-app
            git pull origin main
            npm ci --production
            pm2 restart my-app || pm2 start src/server.js --name "my-app"
            echo "✅ Dev Deployed!"
        env:
          DB_PASSWORD: ${{ secrets.DB_PASSWORD }}

  deploy-staging:
    needs: deploy-dev
    runs-on: ubuntu-latest
    environment: staging
    steps:
      - uses: appleboy/ssh-action@v1
        with:
          host: ${{ secrets.STAGING_HOST }}
          username: ${{ secrets.STAGING_USER }}
          key: ${{ secrets.STAGING_SSH_KEY }}
          script: |
            cd /var/www/my-app
            git pull origin main
            npm ci --production
            pm2 restart my-app

  approval:
    needs: deploy-staging
    runs-on: ubuntu-latest
    environment: production
    steps:
      - run: echo "✅ Approved"

  deploy-production:
    needs: approval
    runs-on: ubuntu-latest
    environment: production
    steps:
      - uses: appleboy/ssh-action@v1
        with:
          host: ${{ secrets.PROD_HOST }}
          username: ${{ secrets.PROD_USER }}
          key: ${{ secrets.PROD_SSH_KEY }}
          envs: NODE_ENV,DB_PASSWORD
          script: |
            cd /var/www/my-app
            git pull origin main
            npm ci --production
            pm2 restart my-app
            echo "🚀 Production Deployed!"
        env:
          DB_PASSWORD: ${{ secrets.DB_PASSWORD }}
