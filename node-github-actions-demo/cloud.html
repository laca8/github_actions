📝 مراجعة سريعة — Q&A

Q1: What is cloud computing?
بدل ما الشركة تمتلك وتدير الـ IT Infrastructure بنفسها، تستخدم موارد حوسبة عند Cloud Provider وتدفع حسب الاستخدام.
Q2: What problem does virtualization solve?
بتسمح بتشغيل multiple virtual machines on one physical server — مع Isolation ومنع تعارض الـ Dependencies.
Q3: VM vs Container? 
VM                    Container
App                   App
 ↓                     ↓
Guest OS              Container
 ↓                     ↓
Virtual Hardware      Host OS Kernel

→ Containers are lightweight compared to VMs
Q4: Is virtualization the same as cloud computing? No.
الـ Virtualization technology، والـ Cloud Computing service delivery model بيعتمد على تقنيات كتير والـ Virtualization واحدة منهم.
Q5: Examples?
AWS · Microsoft Azure · Google Cloud · Google Drive · Microsoft 365 · Dropbox

5 · Benefits of Cloud Computing

كل الفوايد دي بترجع لفكرة واحدة: تاخد قدرات كانت محتاجة Data Center كامل وفريق IT — بضغطة زرار وبفلوس على قد استخدامك.

1️⃣ Scalability — القابلية للتوسّع

Vertical Scaling (Scale Up)

       Before                     After
   ┌──────────────┐          ┌──────────────┐
   │  t3.micro    │   ───►   │  t3.xlarge   │
   │  2 vCPU      │          │  4 vCPU      │
   │  1 GB RAM    │          │  16 GB RAM   │
   └──────────────┘          └──────────────┘

   ✔ سهل جدًا (مش محتاج تغيّر الكود)
   ✘ ليه سقف (Hardware limit)
   ✘ غالبًا محتاج Restart → downtime

Horizontal Scaling (Scale Out)

       Before                        After
                              ┌──────────────────────┐
   ┌──────────┐               │    Load Balancer     │
   │ Server 1 │      ───►     └───┬──────┬──────┬────┘
   └──────────┘                   ↓      ↓      ↓
                              Server1 Server2 Server3

   ✔ مفيش سقف عمليًا
   ✔ لو سيرفر وقع الباقي شغّال
   ✘ محتاج الـ App يكون Stateless
مهم للـ Backend Developer: عشان تعمل Horizontal Scaling لازم تشيل الـ State من السيرفر — Sessions تروح Redis، والملفات تروح S3.

المقياس المعنى السؤال

📝 Q&A

Q1: Scalability vs Elasticity?
Scalability = the ability to grow. Elasticity = automatic scale in/out based on demand.
Q2: HA vs Fault Tolerance?
الـ HA بتقلّل الـ Downtime، الـ FT معناها صفر Downtime عند عطل مكوّن.
Q3: RTO vs RPO؟
RTO = قد إيه هفضل واقع. RPO = قد إيه هخسر بيانات.
Q4: إزاي أعمل App جاهز للـ Horizontal Scaling؟
خليه Stateless → Sessions في Redis · Files في S3 · Database خارجية.

6 · Cloud Pricing & Cost Concepts 💰

ملاحظة: الأرقام هنا للتوضيح فقط — الأسعار الحقيقية بتختلف حسب الـ Region والخدمة وبتتغيّر باستمرار.

1️⃣ Pay-as-you-go

Traditional                          Cloud
──────────────────────────────────────────────────────────
تشتري سيرفر بـ 100,000            تشغّل EC2 بالساعة
   ↓                                  ↓
تدفع كله مقدّمًا                    تدفع على الساعات اللي اشتغلتها
   ↓                                  ↓

مثال: بيئة Dev/Test شغّالة 8 ساعات × 5 أيام = 40 ساعة بدل 168 → توفير ~76%.

2️⃣ CapEx vs OpEx

النوع CapEx OpEx
المعنى تشتري أصل وتملكه تدفع مقابل استخدام
الدفع مبلغ كبير مقدّمًا مبالغ صغيرة مستمرة
مثال سيرفرات + Data Center + رخص فاتورة AWS الشهرية
المخاطرة عالية منخفضة
الاتجاه Traditional Data Center Cloud ✅
جملة الامتحان: Cloud shifts your spending from CapEx to OpEx.

9 · Availability & Reliability

كل قرارات الـ Architecture في AWS بترجع لسؤال: لو الحاجة دي وقعت… هيحصل إيه؟

1️⃣ Availability

                  Uptime
Availability = ───────────────────  ×  100
                Uptime + Downtime
Availability الاسم Downtime / سنة Downtime / شهر
99% Two nines ~3.65 days ~7.3 hours
99.9% Three nines ~8.8 hours ~43.8 minutes
99.95% — ~4.4 hours ~21.9 minutes
99.99% Four nines ~52.6 minutes ~4.4 minutes
99.999% Five nines ~5.3 minutes ~26 seconds
كل «تسعة» زيادة بتزوّد التكلفة والتعقيد بشكل كبير. موقع داخلي للموظفين مش زي نظام دفع بنكي.

2️⃣ Reliability

المقياس المعنى
MTBF
Mean Time Between Failures		 متوسط الوقت بين الأعطال — كل ما زاد أحسن ⬆
MTTR
Mean Time To Repair		 متوسط وقت الإصلاح — كل ما قلّ أحسن ⬇ 
Failure          Failure          Failure
   │                │                │
───┴────────────────┴────────────────┴──────► Time
   │◄──── MTBF ────►│
   │◄─►│
    MTTR

Availability = MTBF / (MTBF + MTTR)

3️⃣ الفرق بين المصطلحات

المصطلح السؤال مثال
Availability هل الخدمة شغّالة دلوقتي؟ الموقع بيفتح ولا لأ
Reliability هل بتشتغل صح باستمرار؟ الـ API بيرجّع نتيجة صحيحة
Durability هل بياناتي مش هتضيع؟ S3 durability عالية جدًا
Scalability أقدر أكبر لما الحِمل يزيد؟ أزوّد سيرفرات
Fault Tolerance الخدمة تكمّل لو جزء وقع؟ سيرفر وقع والباقي شغّال

5️⃣ Redundancy

النمط الفكرة التكلفة / السرعة
Active - Active كل النسخ شغّالة وبتستقبل Traffic أغلى · تحويل فوري
Active - Passive نسخة شغّالة وواحدة Standby أرخص · فيه Failover time

  99.9%  ×  99.9%  =  99.8%        ← الإتاحة بتقلّ ⬇

مكوّنات متوازية (Redundant)
  1 - (1 - 0.999)²  =  99.9999%    ← الإتاحة بتزيد ⬆

📝 Q&A

Q1: يعني إيه 99.99%؟
Downtime مسموح ~52 دقيقة في السنة.
Q2: Availability vs Reliability vs Durability؟
Availability = شغّالة · Reliability = بتشتغل صح · Durability = البيانات مش هتضيع.
Q3: إيه الـ SPOF؟
مكوّن وحيد لو وقع النظام كله يقع — الحل: Redundancy + Multi-AZ + Load Balancer.
Q4: Multi-AZ = Disaster Recovery؟
لأ. الـ Multi-AZ بيحميك من عطل AZ. الكوارث على مستوى Region محتاجة Cross-Region Replication.
Q5: ليه مش كل نظام محتاج Five Nines؟
كل تسعة زيادة بتضاعف التكلفة — القرار حسب تأثير الـ Downtime على الشغل.
